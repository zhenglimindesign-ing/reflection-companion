# 场景示例：从一次交谈到持续使用

**简体中文** | [English](EXAMPLES.md)

以下是展示预期行为与纠正过程的虚构教学示例，不是用户证言或评测实录。返回[概览](../README.zh-CN.md)或[指南](USER_GUIDE.zh-CN.md)。

想先看更生活化的“如何写一篇日记”，从[日记演示](USER_GUIDE.zh-CN.md)开始。下面六段侧重说明能力与纠正，不是新用户必须照做的步骤。

## 1. 回顾：判断标准的变化

**用户：** 这两份带日期的笔记有什么变化？早些时候：“选 A，因为最快。”后来：“选 B，因为撤回成本小。”

**Companion：** 在这两份笔记里，可逆性取代速度成为更重要的标准。这支持对本次决定的观察，不足以证明你整个人的风险态度改变了。

**用户：** 两份笔记之间预算变了。

**Companion：** 那条件变化可能解释了标准变化。更准确的观察是：你根据新预算调整了这个决定。比较当时可用的选项可能更有帮助。

**关键：** 比较前后依据，保留情境，不编造性格成长故事。

## 2. 挑战：准备还是推迟

**用户：** 我已经收集三份报价，还在继续要。我是不是拖延？

**Companion：** 有可能，但数量本身不能说明。如果遗漏了一项重要成本，继续了解有意义；如果只重复回答同一个问题，价值可能很小。哪个不确定性会改变选择？

**用户：** 是否包含维护。

**Companion：** 那就直接确认维护范围。目前证据支持补上具体信息，不能据此给你贴“拖延”的标签。

**关键：** 同时检查问题中的预设和当前做法，提出有用的区分。

## 3. 拓展：一个有用的新角度

**用户：** 我选兴趣时总想怎样进步最快。带我换个角度。

**Companion：** 可以把最初几次当作体验采样：什么让你投入、想再来一次、喜欢怎样的环境。这个角度与你的选择相关，因为技能提升只是继续一项兴趣的可能理由之一。可以比较一次独处和一次结伴体验，不急着长期承诺。

**用户：** 我已经知道自己更喜欢独处。

**Companion：** 那这个比较不会增加多少信息。如果你还不确定，可以比较一次有明确步骤的练习与一次自由探索。

**关键：** 解释关联，回应用户已经知道的东西，不强求“新颖”。

## 4. 保留与积累：纠正后再使用

**用户，在已开启保存的工作区：** 保存这条虚构练习：“我不喜欢变化。”

**Companion：** ［程序保存成功后，报告实际记录 ID 和位置。］

**用户：** 太笼统了，纠正成“在这个项目里，我更偏好容易撤回的改变”。

**Companion：** ［程序纠正成功后报告新 ID，旧记录被标记为已取代。］

**用户，在使用同一记录库的新 chat：** 这项练习里有什么需要记住？

**Companion：** 当前有效修正限定在这个项目：你更偏好容易撤回的改变。以前“我不喜欢变化”的说法已经被取代，不应继续描述现在的你。

**用户：** 删除这个练习。

**Companion：** ［检查并定位该练习的具体记录，成功删除后报告结果。］

**关键：** 保存、纠正和后来使用是不同动作。方括号表示必要的真实工具结果，没有伪造“已保存”。

## 5. 探索：不知道怎样开始，选中后实际聊起来

**用户：** 最近有什么适合尝试的自我探索方式？我今天想轻松一点，也不想先翻历史。给我几个差别大一点的，我选一个后直接开始。

**Companion：** 可以试“一个值得问的问题”：找一个你今天想弄清的小问题；或者“一次好奇的采访”：我根据你的回答继续问。两者都不需要读取历史，你可以选，也可以让我代选。

**用户：** 采访。先问一个。

**Companion：** 最近有没有一件你想做、但后来没有做的事？可以选很小的事情。

**用户：** 本来想上晚间绘画课，但这周取消了。

**Companion：** 取消前，最影响你的是什么：时间安排、课程内容，还是别的原因？

**用户：** 只有十分钟空闲。我其实还挺想画。

**Companion：** 从这个例子看，兴趣还在，当前可用时间与课程形式不合适。可以继续聊：如果只画十分钟，你最愿意画什么？

**用户：** 我想随手画，不想又给自己安排一个任务。今天先聊到这，不保存。

**Companion：** 明白，这次就停在这里，不保存这段讨论。

**关键：** 推荐之后进入同一 chat 的交谈；具体解释来自本次回答；用户可以拒绝行动建议和保存。玩过一次不等于完成测评，临时反馈也不会自动升级成长期偏好。浏览[完整玩法库](https://github.com/zhenglimindesign-ing/reflection-companion/blob/main/docs/PROMPTS.zh-CN.md)可按标题直接开始。

## 6. 周回顾：把一周的变化联系起来

*材料为虚构：上周的已保存问题是“要不要接额外任务”；本周三段材料分别记录周一询问收益、周三发现与已有承诺冲突、周五对方提出缩小合作范围。助手需要实际读到这些材料，不能根据任务标题补造过程。*

**用户：** 回顾本周这三段讨论，不要把每天的摘要拼一遍。也结合上周那个问题。

**Companion：** 在这三段材料里，问题从“收益值不值得”变成“怎样避免冲突”，再变成“是否接受小范围合作”。这周增加的可用选项是缩小范围，而不是只能接或不接。上周的问题现在解决了吗？

**用户：** 我已接受小范围合作。但不是我想到缩范围，是对方提的。

**Companion：** 对，提案应归于对方；你的决定是接受这个调整后的范围。不能把它写成你主动发现了新策略。旧问题可以视为已解决，后续若有需要，再看这个范围实际是否合适。

**用户：** 这样准确。保存这个决定，把上周的问题标为解决；别自动加新任务。

**Companion：** ［读回当前记录并核对权限，实际保存决定和更新旧问题状态后，报告成功的记录 ID 与位置；若只完成一部分，分别说明。不创建定时或待办。］

**关键：** 周回顾的价值在于联系前后、识别新增信息、修正归因并关闭已经解决的问题。相同用法也可以由你明确设置的宿主定时任务触发；示例不代表已经开启定时。

# Reflection Companion 场景与进阶指南

**简体中文** | [English](USER_GUIDE.md)

[产品介绍与快速开始](../README.zh-CN.md) · [平台安装详情与验证范围](PLATFORMS.zh-CN.md)

第一次使用所需的产品介绍、安装方法和起步示例都在 README。本指南供你按需深入日记、周回顾、反复模式、探索、保存与定时，说明怎样选择材料、继续讨论和保留结果。说明对应公开 Alpha v0.5.6，内置库有 23 条双语探索。

## 1. 选择材料，从已经在想的问题继续

按 [README](../README.zh-CN.md) 安装并开始后，可以用现成的讨论，也可以讲一件眼前的事。材料的选择会影响这次能够讨论的范围。

如果你已经用 AI 讨论过很多事情，可以说：

> 帮我回顾这周关于这个项目的讨论。我在意的标准发生了什么变化？先说明你实际能读到哪些材料；暂时不保存。

它应先取回实际材料，再给出有依据的比较。若宿主无法访问历史，应说明具体缺口，改用当前对话或你选定的几段材料，不假装读过整个账号，也不要求你重新写完整档案。

没有历史同样可以开始：

> 我还在反复修改这个方案，拿不准哪些准备是必要的。帮我检查判断，一次只问一个会影响结论的问题。

回答后，你可以补充事实、反驳解释、换一个方向或结束。普通的一次有效讨论不需要沉淀结论。

## 2. 按当前需要选择场景

下面是几种常见用法，以及各自需要的材料和可期待的结果。直接描述你的需要即可。

| 你现在想做什么 | 材料从哪里来 | 直接说 | 应得到什么 |
| --- | --- | --- | --- |
| 一天结束，整理日记 | 当天可访问的对话，或你愿意讲的一件事。 | “回看今天的材料，整理一篇短日记。缺的地方再问我，先别加成长总结。” | 有依据的经历与感受；模型推测单独说明。 |
| 一周结束，看见变化 | 约定范围内的聊天或日记文件。 | “比较这周前后的判断，看看哪些变化有证据。” | 前后比较、情境变化和仍不能判断的部分。 |
| 想看看有没有反复出现的模式 | 一段时间内多个可访问的相关讨论，最好包含不同情境。 | “回看这段时间的讨论，有没有什么反复出现、但我自己可能没注意到的思考方式？先把它当成待验证的观察。” | 具体证据、适用情境与反例／限制；不把单次事件升级成稳定人格。 |
| 一段经历告一段落 | 一个月、一个项目或主题的指定材料。 | “帮我回顾这段经历从开始到现在：我一开始是怎么想的，后来哪些判断变了，哪些标准一直没变？” | 联系一个阶段的经历、变化和仍值得想的问题。 |
| 一个决定拿不准 | 当前讨论，必要时参考相关历史。 | “找一个最可能改变结论的信息，也考虑支持我的解释。” | 具体信息缺口或替代解释；可以支持当前判断。 |
| 想拓展认识 | 当前问题或选定的历史主题。 | “给我一个有关联、但惯常思路之外的视角。” | 新角度、与问题的联系，以及继续探索的方式。 |
| 不知道问什么 | 不需要历史也能开始。 | “帮我选一个可以更了解自己的问题，直接问我。” | 直接提出一个问题；想自己选时可要两三个选项。 |
| 想接着上次聊 | 当前对话或已授权保存的记录。 | “读上次那个收获，结合这次情况重新判断。” | 以前的限定和修正仍然有效，结论可以再次改变。 |
| 睡前只想聊聊 | 你愿意分享的片段。 | “今天不分析，聊一件小事就好。” | 自然交谈，不强制得出成长结论。 |

已有材料优先。日记是一种可选表达形式；这个产品并不要求你从每天手工输入开始。

### 日、周、月、季度、年的模板与选择

**v0.5.0 提供五个周期的双语模板和完整虚构示例。** 模板约定写作结构，模型根据实际材料成文。选择模板不会扩大来源权限；本轮宿主验证范围见[平台记录](PLATFORMS.zh-CN.md)。

| 你可以直接说 | 默认关注什么 |
| --- | --- |
| “把今天这些片段写成日记。” | 经历、感受、值得留下的瞬间；第一人称成文，不自动加心理分析。 |
| “看看这周发生了什么、哪些判断变了。” | 事实、变化、有限观察、未决问题；最多一个可跳过的实验和一个结尾问题。 |
| “这个月哪些事情更有依据，我的注意力去了哪里？” | 月内主线、证据、生活空间，检查旧解释；不自动布置下月任务。 |
| “回看这个季度，有没有反复出现但有条件的模式？” | 跨月轨迹、投入与需要、模式成立及不成立的条件。 |
| “整理这一年，别替我编一个成长故事。” | 不同阶段、实际选择、想保留的经历、仍有的矛盾和已表达的意愿。 |

不必背固定触发词，“整理刚过去的三个月”也可以。时间段不明确且会影响结果时再澄清。“记录这个报错”“写公司年报”按实际任务处理。材料少就写小范围，不为完整模板补经历；选择年度模板不扩大检索权限。

起步可选“尽量保留原话”“整理成文”或“Long View 式反思”。还可调整篇幅、段落或栏目、人称、标题、语言、语气、主题与排除项、原话数量、来源附录、AI 观察深度、收获、知识、精彩瞬间、未决问题、实验、结尾问题和时间窗口。组件按适用选项关闭、放进正文或单列。深度更高仍须保留依据与反例；日记不必每天有收获。

| 这句话 | 实际效果 |
| --- | --- |
| “今天短一点，不分析我。” | 只调整这次，不保存长期偏好。 |
| “以后周回顾多保留原话，不要实验和最后的问题。” | 在已选、已授权的本地记录库保存周偏好，保留其他周期设置；没有记录库时先在本 chat 生效，说明跨 chat 尚未保存。 |
| “保存这篇到我选的目录。” | 导出本篇文件，成功写入并核对后报告位置。 |
| “把这句收获留到以后。” | 保存选定内容及其确认状态，不把整篇 AI 解释变成长期结论。 |
| “每周日 19:00 做这个。” | 补齐必要时区、来源、目的地和保存方式，通过可用宿主工具设置。 |
| “这个能定时吗？” | 说明能力，不自动创建任务。 |

优先级为“本次要求 > 已保存周期偏好 > 已保存通用偏好 > 默认值”。移除周期覆盖项后通用偏好仍适用。无需手动编辑 JSON。关闭连续性后不读取已保存偏好，本次选择仍可使用。详见[完整成品与关闭分析的变体](../plugins/reflection-companion/skills/reflection-companion/assets/examples/reviews.zh-CN.md)和[具体选项及保存规则](../plugins/reflection-companion/skills/reflection-companion/references/preferences.md)。

## 3. 一个具体例子：我还喜欢画画吗？

以下是编写的教学示例，不是真实用户经历或评测结果。三段讨论分别使用当天的经历、两份记录和你选择保留的收获。

**当天，整理经历。** 你说：“今晚又没画画，我是不是已经不喜欢了？”讨论中补充：“下班后只剩十分钟，但课程要一小时。”这次能够确认的是课程时长与可用时间冲突。日记可以记下经历和疑问；仅凭没有上课，还不能判断兴趣已经消失。

**周末，联系前后。** 你提供两份记录：周二错过了一小时课程；周五随手画了十分钟，觉得很开心。回顾可以指出：“这两份记录支持你仍享受画画；目前可能更适合短时、自由的形式。”这比把两天的摘要拼起来多了一层理解，也保留了“只基于两份记录”的范围。

**以后，继续或修正。** 你可以要求保留：“这周，十分钟随手画比一小时课程更适合我的时间安排。”下一次读到这条记录，可以接着讨论现在的情况。如果你后来更喜欢系统课程，就修正这条收获的适用范围。成功保存或修正后应报告实际位置或记录 ID；以前的理解可以随新的经历改变。

这三次讨论分别帮助你厘清一次经历、发现两次经历间的联系、把收获带入后来思考。是否保存由你选择；以后继续时需要实际读到记录。更多细分对话见[完整示例](EXAMPLES.zh-CN.md)。

## 4. 探索新问题：题库是材料，Skill 负责带着做

直接说“帮我选一个可以更了解自己的问题，直接问我”，它会从内置库选一个并开始，不要求先选内置／网络或开启保存。没有历史时可用“一个值得问的问题”或“一次好奇的采访”。“轻一点／深一点／犀利一点／好玩一点”调整语气，不改变证据要求；想自己选可以要两三个选项。“换个方向”应用你的反馈，只有明确问新内容才读动态目录。

历史型问题包括“一个可能的盲区”“我可能看错自己的地方”“快一点，还是影响大一点？”“当下什么最重要？”和“如果只剩这些痕迹”。它们先核对真实可访问材料的时间与领域，比较证据、反例及更正。幸福感改变是待验证建议；优先级不能只按聊天频率；第三人称介绍要区分依据、推测和记录无法说明的部分，默认不加入死亡设定。材料不足时说明判断范围或保留未解问题，不把它包装成完整人生画像。

探索包括随包基础库、独立更新的动态目录、针对当前处境设计和即时联网搜索。23 是当前基础库的条目数，不是整个探索内容的上限；动态目录也不要求为了每次新增内容重新安装 Skill。

可以点名“善意吐槽”，也可以说“找一个适合现在的探索方式”。选中后就在当前对话开始，接着你的回答追问、核查和修正。只复制一个问题去普通聊天同样可行；Skill 的作用是让选择、执行和后续衔接使用同一套方法。

| 来源 | 怎样获得 | 能说到什么程度 |
| --- | --- | --- |
| 23 个内置原创玩法 | 无需联网，可按主题或所需材料选择。 | 基础方法，不是热门榜。 |
| 针对当前情境设计 | 结合你的问题，用自己的话生成。 | 为本次讨论设计，不假装来自网络。 |
| 独立探索目录 | 问“有什么新的”时读取公共目录，失败则说明使用了哪天的随包快照。 | 最近收录不等于最近首发；超过 30 天未核查应提示。 |
| 即时联网搜索 | 请求近期公开灵感时核查原始页面、日期和可见互动信息。 | 没有热度证据，就不称热门；搜索摘要不能替代原文。 |

例如：“最近有什么新问题？不要再推荐优势主题，给我两个不用历史的方向。”候选可以包括“此刻的三行自画像”：现在在意什么、正在尝试什么、拿不准什么。它的后续价值可以是过段时间重新回答后比较变化，而不是必须答完整个题库。

你可以说“这个聊过了”“不符合我”“轻一点”“停”。当前对话中的反馈立即有效；跨 chat 去重需要可用的展示记录，长期偏好需要你的保存指令。个人回答不会进入公共题库。

目录更新可以独立于插件版本，但内容仍需有人实际搜集、核查和发布。本版本没有开启定时采集服务；公开目录会在你请求新内容时读取。基础库、随包快照和即时搜索可分别使用。维护流程见[维护说明](MAINTAINING.zh-CN.md)。

## 5. 保存：三种记录分别是什么

| 记录 | 所在位置 | 如何使用 |
| --- | --- | --- |
| 原始聊天 | 由 Codex、Claude 等宿主管理。 | 读取实际获准且可访问的部分，不额外复制全部账号历史。 |
| 日记、周记等可读文档 | 你选择的目录或下载文件。 | 明确要求导出后生成；可以自己阅读和编辑。 |
| 选定的收获与修正 | 个人工作区的 `.reflection-companion/state.json`。 | 用于以后继续讨论，区分你确认的内容和待讨论的观察。 |

第一次保存时说：“帮我设置本地收获库，先说明位置；只保存我明确要求的内容。”选择一个个人工作区和时区。目录为本地明文，应说明位置、排除普通 Git 跟踪和备份含义。插件安装目录和公开产品仓库都不应充当个人记录位置。辅助程序需要 Python 3.10+；安装 Skill 本身不代表同意保存。

位置确定后可以说：“把这次结论保留，但只限于这次情境。”“看看保存了什么。”“修正上一条，以我刚才这段为准。”“删除那条记录。”助手应执行后核对结果，再报告路径或记录 ID；没有成功写入就不能说已保存。你不需要手工编辑 JSON。

保存日记可以另行选择 `journals/daily/日期.md`、周回顾选择 `journals/weekly/起止日期.md`。这只是建议结构，不会自动创建。保存整篇日记不等于同意提取长期个人结论。遇到已有文件，应先读取并保留你的修改，避免重复运行覆盖它。

月、季度、年也可各用独立目录。已连接且具备写入能力的云端工具（例如 Google Drive）可以在你指定目的地并授权后导出文档；格式设置本身不会连接云端。工具不可用时说明限制，不声称已写入。云端导出不表示 `.reflection-companion` 已有云同步能力。

跨 chat 继续时，使用同一工作区或告诉助手原来的位置。位置未知时先确认，不另建一个空库；先读取再解释。在 Claude 网页中可说：“导出为可下载的 Markdown，不写入收获库。”回复和导出文件默认跟随你当前对话的语言，无需额外指定；想翻译时再说明目标语言。点击文件卡片的 Download，再打开核对；[平台指南](PLATFORMS.zh-CN.md)有真实截图。网页临时文件不等于电脑存档或跨 chat 永久保存，后续对话可以由你重新提供导出文件。关闭保存不删除原始聊天或已有导出；删除 Companion 记录也不删除宿主和备份中的副本。

## 6. 主动来聊与定时执行

你发消息是主动使用；宿主到约定时间运行同一套方法是定时使用。定时不会增加材料访问权限。

| 定时类型 | 到点做什么 |
| --- | --- |
| 提醒我写日记 | 发一个邀请，等你回应；你没说的经历不能代写。 |
| 自动生成日记草稿 | 根据约定来源写草稿，标出覆盖不足；无材料时说明或按约定跳过。 |
| 自动周回顾 | 读取约定时间段内的聊天或日记，比较前后。 |
| 推荐新探索 | 查目录或联网找少量选项，不凭空分析你的个人经历。 |

先手动做一次你想定期获得的结果，再提出具体设置请求，例如：“每周日 20:00，按 Asia/Shanghai 回顾此前七个完整自然日，只读我选的日记目录；发在当前 chat，先不写文件。没有材料就说明。”助手补齐实际需要的时间、时区、来源、排除范围、输出位置与保存权限，检查可访问性后通过宿主工具创建。

**任务配置成功与首次实际送达分别核验。** 安装 Skill、写好一段定时提示或拥有记录库，都不代表已经启用定时。Codex 的本地任务依赖设备和应用可用；其他宿主按当前账户工具判断。暂停任务应修改宿主任务；关闭保存不会自动暂停发送，暂停任务也不会删除日记。

## 7. 更新与反馈

基本安装步骤在 [README](../README.zh-CN.md)。你可以直接说“检查 Reflection Companion 有没有新版”“升级到最新正式版”或“退回上一个版本”。检查只返回当前版本、可用版本和主要变化；明确要求升级或回退后才改变安装。固定版本不会自动跳到新版，也没有后台更新提醒服务。

更新同一个 Skill／插件，保留旧版恢复依据和原来的日记、偏好目录。回退的是程序版本，期间新增的记录不会倒退；较老版本可能不使用新增的偏好，但不应删除它们。升级完成会说明实际安装版本、核验结果、恢复位置及是否需要开新 chat。各平台的方式不同，见[平台指南](PLATFORMS.zh-CN.md)。

当前公开版本为 0.5.6，提供 Codex 的检查、准备、升级和回退助手；已有 0.5.0 用户可以让当前宿主通过经审查的当前版本协助首次更新，不必自行寻找 ZIP。Claude Code 项目 Skill 和 Claude 网页上传包按各自渠道更新，不能把 Codex 的安装成功当作 Claude 已更新。

手机上的[文字示例](MOBILE.zh-CN.md)用于试一次方法，不自动携带 Skill 的引用资料、记录程序、跨 chat 状态或定时。不能把这段 prompt 说成已完成国内原生适配。

反馈只需说明尝试的场景、预期与实际结果。公开反馈可以用虚构小例子，不必提交私人聊天。[反馈入口与维护方式](MAINTAINING.zh-CN.md)。你可以在任何时候停止，或纠正模型对你的理解。

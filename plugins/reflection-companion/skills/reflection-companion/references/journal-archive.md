# Continuing and organizing a journal archive

Read for continuing an existing archive, bulk historical backfill, or changing its organization. [Artifacts](artifacts.md) govern the writing; this contract governs source coverage, containers and verified delivery. It does not grant access or saving permission.

## Recover the existing contract

Use the current user's instructions first, then an accessible earlier user agreement, then the existing archive as evidence of its implemented convention. An earlier AI proposal alone is not an accepted agreement. Distinguish a verified existing structure from a recovered original agreement; identify unresolved details without asking the user to restate information you can retrieve.

Before choosing folders or creating files, inspect the selected destination and at least one representative completed document. For a tabbed document inspect native tab names, IDs, order, nesting and representative bodies. A flattened text export cannot establish that tab structure. Resolve only details needed for the authorized change:

- Destination, container period (for example one month per document), document name and date/timezone basis.
- Entry unit (tab, section or individual file), titles, chronological order and nesting.
- Placement of daily entries and weekly/monthly/quarterly/yearly reviews; do not infer every period's placement from daily examples alone.
- User narrative, AI material, source notes and draft/completion labels.
- Handling of missing source days, existing entries, corrections and duplicate writes.

Keep required invariants distinct from configurable presentation. Dates, attribution, accurate coverage, human corrections and readback are required. Container period, headings, tabs versus files and narrative voice follow the user's convention or current choice. Templates are editable writing scaffolds, not a mandatory archive layout. Do not silently replace monthly documents with daily files, migrate a folder tree, flatten tabs, or impose a new AI-observation section.

Recover corrections as well as the initial proposal. A later user correction about date tabs overrides an earlier AI proposal to separate tabs by narrator. When the accepted diary distinguishes a low-interpretation user narrative from selected AI answers or knowledge, retain that distinction. Selected AI material is not permission for a new psychological commentary; it may be empty when no supported selection is useful. Map supported template components into the accepted headings and explain omitted components in the delivery receipt when requested, rather than replacing the user's structure or filling unsupported slots.

For example, an implemented monthly document may have one `MM-DD` tab per day and a final monthly-review tab. Preserve that structure when continuing it. Quarter/year placement remains unresolved unless supported by an agreement or existing example. Present a bounded proposal for that unresolved placement while continuing independent source work. Do not encode a person's private folder IDs or convention as the Skill's universal default.

When the user wants contiguous reading, keep the day's narrative and corresponding week review together. A configurable option is one document per quarter, one tab per week with daily sections followed by the weekly review, month-review tabs after the relevant weeks and a final quarter-review tab. Monthly containers are also valid when smaller files matter more. Explain the tradeoff: quarterly containers reduce switching and keep period reviews together; monthly containers are smaller but create more boundaries. Choose and state a cross-month/quarter week rule so a week is not silently split or a date duplicated; link its single authoritative location from the adjacent container. Container period and entry unit are independent choices, not a replacement for the writing templates. Preserve original files when the user requests new comparison copies.

If the user requests separate new documents for comparison, preserve every original file. Copy the relevant native document when its tabs/styles are the governing reference, then adapt the copy to the requested period and template. Use distinct names, verify the original and new IDs, and direct every write to the new ID. An existing archive discovered during the task is a baseline, not this task's output. Do not rename a chat-only draft as the user's existing archived diary.

## Personal storage boundary

Use the user's chosen private destination for personal records, source indexes, quotes and verification receipts. Never select a product/code repository merely because it is the current directory or has an `outputs/` convention. This applies to private repositories, ignored files, scratch directories, generated packages and Git history as well as public repositories. Product instructions, templates and fictional fixtures may live in the repository; real source links and biographical examples do not belong in product-development reports.

If the user explicitly chooses a repository as a personal journal destination, resolve that choice and its publication implications rather than assuming it from a technical workspace. A prohibition on repository storage applies to all task-generated copies. For cloud authoring, keep working content in memory when supported; if a required connector workflow needs local staging, use a dedicated temporary location outside all code repositories, restrict access, and remove task-created staging after verified cloud delivery. Do not silently keep a second personal archive or backup.

## Establish coverage before bulk writing

Apply [source readiness and targeted repair](source-readiness.md) before synthesis. Its read-only check distinguishes a complete selected corpus from unknown account history and prevents a recent index alone from passing as complete. A saved coverage register is a work receipt, not a successful backfill.

For a request covering all conversations or every day since an earlier archive, keep a concise coverage register in the authorized delivery workspace, or in the chat if saving is not authorized. It must distinguish:

1. Requested dates/cutoff, timezone, topics/exclusions and the last verified saved entry. An assumed start date is labeled as an assumption.
2. Discovery surfaces searched, their date bounds/page limits and whether they expose a full archive or a recent index only.
3. Relevant source IDs/links, actual message dates, source type and retrieval status: retrieved, truncated, inaccessible, or completeness unknown. Summaries, titles and previous AI reviews are discovery aids; they do not substitute for message text.
4. Attachments or referenced files that could materially change interpretation, and any unresolved gap.

Use available pagination when missing evidence matters. If a recent listing is unexpectedly narrow, try a relevant accessible archive/search surface or known source IDs. A cursor with no further page establishes only the end of that returned surface, not completeness of the account. Browser-rendered snippets and automated-only replies also do not establish complete user participation. Do not scan unrelated home/session logs or ask for credentials to simulate an archive. After an actual access limit, report the specific blocked source and complete independent work; request an export or source location only when supported retrieval cannot obtain necessary material.

Do not calculate account-history coverage from the number of dates represented in a few retrieved snippets. Coverage against a known, bounded supplied corpus can be measured; unknown account completeness remains unknown.

Track source coverage separately from editorial coverage and saved delivery. Follow the artifact's recording criteria rather than requiring every examined question in the body. Justified incidental omissions do not remain on the catch-up queue. If a verified scoped day's material contains only such lookups, record that it was examined without creating a filler diary or describing it as a quiet day; preserve any remaining broader-source gap separately.

Insufficient evidence for full backfill means the backfill remains incomplete. Do not silently substitute a handful of sample diaries, a narrow review or previous AI summaries and call the original task done. If the user wants partial drafts, label them with their actual source range and record what is still missing. Missing material is not a quiet day; do not borrow neighboring days' experiences to fill a tab.

## Resolve completed periods

Check the current date/time and local timezone before deciding which periods ended. For calendar periods, a month, quarter or year is complete only when its end precedes the cutoff. Preserve custom intervals when requested. A partial archive start does not become full-period coverage: label a review's available source range accurately. An unfinished year is not an annual review merely because a quarter ended. If no requested completed year exists, say so without manufacturing one.

Period reviews compare original material at their own scale. Use lower-period reviews as indexes and revisable baselines, check consequential facts and corrections against original sources, and avoid concatenating daily/monthly prose into a longer growth story.

## Save and verify the authorized package

Distinguish a request to write in chat from a request to save or continue records at a selected location. Explicit saving/continuation authorization persists for the requested scope; do not ask again at each normal step. Creating a readable journal does not enable Companion state or scheduling. An organization suggestion alone does not authorize moving existing records.

Before editing, read current content and native structure. Match period/date keys to existing entries, preserve human corrections and handle concurrent revisions using host-supported safeguards. Avoid duplicate tabs/documents on retry. If the connector cannot preserve the agreed structure, explain that specific limitation and prepare a reviewable alternative without silently changing the contract.

After saving, read the actual destination and check entry text, dates, quotes, attribution, tab/section placement and order, plus preservation of existing material. Report document/file links, tab names or links when available, draft/completion status, source gaps and what remains. Creating an empty container or returning a successful API status is not completed delivery. See [delivery guidance](delivery.md).
